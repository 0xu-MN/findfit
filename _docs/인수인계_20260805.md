## 1. 프로젝트 관리 개선

- **리뷰 원본 보기** ([app/builder/reports/[id]/raw/page.tsx](app/builder/reports/[id]/raw/page.tsx) 신규) — AI가 요약한 리포트와 별개로, 리뷰어가 실제로 제출한 답변 원문을 문항별로 그대로 보여주는 화면. 이름/닉네임 대신 "리뷰어 A · 여성 · 26세 · PM" 식 익명 라벨만 노출([app/api/projects/[id]/raw-reviews/route.ts](app/api/projects/[id]/raw-reviews/route.ts)).
- **재무 정보 입력(사후 입력 가능)** — 등록 마법사에서만 입력 가능하던 예상 판매가/원가/마케팅예산을, 프로젝트 상세 화면과 리포트 화면 양쪽에서 나중에 입력/수정 가능하게 함([app/api/projects/[id]/financials/route.ts](app/api/projects/[id]/financials/route.ts)). 리포트 화면에서 저장하면 자동으로 리포트를 재생성해서 즉시 반영.
- **완료 프로젝트 필터** — 프로젝트 목록에 상태별 탭(전체/작성중/진행중/분석중/완료) 추가 + 좌측 사이드바에 "완료된 프로젝트" 메뉴 신규.
- **리뷰어별 의견 카드를 페르소나 카드 스타일로 개편** — 아바타(성별에 맞는 프로필 사진, `public/avatars/`), PROFILE/PERSONALITY/SCENARIO/PAIN POINT/NEEDS 섹션 구조 (사업주가 준 참고 이미지 스타일).

## 2. 라운지/인사이트 버그 수정

- **글 작성해도 홈 화면에 안 보이던 버그** — 홈의 "지금 FindFit에서 일어나고 있어요" 라운지 미리보기가 정적 샘플 6개만 보여주고 실제 API를 안 쓰고 있었음(`components/shared/HappeningSection.tsx`). 실제 `/api/lounge/posts` 연결.
- **글 두 개씩 올라가던 버그** — "올리기" 버튼에 제출 중 잠금이 없어서 연타 시 중복 POST. `submittingPostRef`로 가드.
- **리포스트가 "인용: ○○" 텍스트로 어색하게 나오던 것** → 원글을 카드로 감싸는 스레드 스타일로 개편(`QUOTE_DELIM` 구분자로 파싱, `components/shared/SharedLoungeFeed.tsx`).
- **"내가 쓴 글" 매칭 버그** — 서버는 `users.nickname`, 클라이언트는 `auth user_metadata.name`으로 비교해서 서로 어긋나면 매칭 자체가 안 되던 구조적 버그. `author_id` 기반으로 교체(다른 세션 커밋 `f04fdbc`).
- **관리자 라운지 관리 패널 신규** — `/admin/lounge`, 부적절한 글 삭제 가능(다른 세션 커밋 `f04fdbc`).
- **댓글 입력 한글 IME 중복 버그** — 한글 조합 중(예: "ㅎㅇ" 입력 후 Enter) 조합이 끝나기 전에 Enter 핸들러가 먼저 발동해서 마지막 글자가 중복 입력되던 문제. `isComposing` 가드 추가(라운지+인사이트 댓글 둘 다, 다른 세션 커밋 `f04fdbc`).
- **리포트 리뷰어 아바타 성별 매칭** — 성별에 맞는 프로필 사진을 리뷰어 태그 해시로 랜덤 배정, 성별 미입력이면 사진을 지어내지 않고 빈 아이콘 표시(다른 세션 커밋 `f04fdbc`).

## 3. FIT 크레딧 → 준비중, 캐시→포인트 용어 변경

- FIT 크레딧(지갑) 페이지 → "준비 중" 안내로 교체(기존 조회/렌더링 로직은 삭제 안 하고 git 히스토리에 남겨둠 — 크레딧 시스템 존속/폐지가 아직 미확정이라서).
- 등록 마법사·요약 패널의 "캐시" 표기를 전부 "포인트"로 변경(순수 텍스트 교체, 계산 로직은 안 건드림).

## 4. 🔴 리포트 콘텐츠 — 반복 수정된 부분 (가장 중요)

사업주가 레퍼런스 이미지 4장(순위 리스트, 카드형 미니차트, 버블/키워드 클러스터, Overview 슬라이드)을 주고 그 스타일대로 만들어달라고 요청했고, **이 과정에서 같은 부분을 3~4번 다시 고쳤습니다.** 다음 담당자가 또 같은 시행착오를 반복하지 않도록 "무엇을 왜 틀렸고 최종적으로 뭘로 정착했는지"를 정확히 남깁니다.

### 4-1. "문항별 응답 요약" — 순위 막대 스타일 (최종 확정본)
**시행착오**: ① 처음엔 1위만 색칠된 알약 + 2위 이하는 무채색 플랫 리스트로 만들었다가 → ② "80%면 80%만큼만 채워져야 한다"는 지적에 막대 트랙+채움 방식으로 바꿨는데 이번엔 텍스트를 막대 **위**에 별도 줄로 뺐다가 → ③ "레퍼런스 이미지를 안 보는 거냐"는 지적에 다시 1위만 알약으로 되돌렸다가 → ④ "그래도 막대 길이는 비율마다 달라야 한다"는 재지적에 최종적으로 **"막대 안에 텍스트를 얹고, 막대 길이는 응답 비율(%)만큼"** 으로 정착했습니다.

**최종 구현** ([components/report/StandardReportView.tsx](components/report/StandardReportView.tsx)의 `문항별 응답 요약` 섹션):
- 각 옵션 행 = `relative` 컨테이너(트랙, 연한 회색 배경) 안에 `absolute` 위치의 채움 막대(`width: {pct}%`)를 깔고, 그 위에 `z-10`으로 순위·라벨·%를 텍스트로 얹는 구조.
- 색상은 순위별 **고정 색**(오렌지 계열 5단계, `#F77019` → `#FFE6D2`)이며 opacity 블렌딩이 아님 — 처음에 opacity로 흐리게 했더니 연한 회색 트랙과 거의 구분이 안 돼서 "안 보인다"는 피드백을 받았던 부분.
- 글자색은 항상 다크(`text-[#1D1C1C]`)로 고정 — 막대 색이 진하든 연하든 어느 위치에서나 읽히게.

### 4-2. "성별에 따른 응답 차이" → "인구통계별 응답 차이"로 확장
사업주가 "성별뿐 아니라 연령대·직군별로도 보여달라 했는데 왜 없냐"고 강하게 지적한 부분입니다. 확인 결과 **정말로 성별만 구현돼 있었고**, 이번에 `lib/ai/generateReport.ts`의 `buildDemographicBreakdown()`을 일반화해서 성별/연령대/직군 세 축을 다 계산하도록 고쳤습니다(`buildGroupBreakdown()` 헬퍼로 추출, 세 번 재사용).

**추가로 발견한 진짜 버그**: 원래 "그룹당 최소 2명 이상 응답"이라는 조건이 있었는데, 실제 PUBLICA 프로젝트 데이터(리뷰어 5명, 성별 1남/1여, 연령대 4:1)로는 **어떤 그룹도 2명을 못 채워서 이 섹션 자체가 항상 텅 비어 있었습니다.** 그룹당 최소 1명으로 완화했습니다(대신 카드에 "N명" 표시로 표본 크기를 그대로 드러내서 소규모 표본이라는 걸 화면에서 알 수 있게 함). **직군 축은 domain_tags 입력률이 여전히 낮아서 지금도 거의 항상 빈 채로 나올 수 있습니다** — 코드 문제가 아니라 데이터 문제이니, `reviewer_profiles.domain_tags` 채움률을 다시 확인해보고 판단할 것.

화면은 성별/연령대/직군 세 개의 소섹션으로 나뉘어 각각 독립적으로 렌더링되고, 데이터가 없는 축은 그 소섹션만 자동으로 안 보입니다(`DemographicBreakdownSection` 컴포넌트).

### 4-3. "반복되는 주제" — 버블 클러스터
**시행착오**: 처음엔 `flex-wrap`으로 원을 나란히 늘어놓기만 해서 "단순 나열이지 다이나믹한 그래프가 아니다"라는 지적을 받았고 → 필로택시스(해바라기 씨앗) 나선 배치로 바꿨는데, 반지름 계산이 원 크기에 비해 너무 작아서 **원들이 서로 텍스트를 가릴 정도로 겹치는** 문제가 생겼습니다 → 최종적으로 **그리디 충돌 회피 팩킹**(각 원을 나선을 따라 배치하되, 이미 놓인 원들과 최소 간격 이상 떨어질 때까지 반지름을 늘려가며 위치를 찾음)으로 수정했습니다.

색상도 기존 원색 조합이 "안 이쁘다"는 피드백을 받아서 좀 더 선명한 팔레트(`#FF6B6B`, `#4D96FF`, `#6BCB77` 등)로 교체했습니다.

### 4-4. "Overview" 섹션 (신규)
사업주가 레퍼런스 이미지로 보여준 "DESK RESEARCH" 스타일 요약 슬라이드를 본떠, 리포트 최상단에 새로 만들었습니다(`app/builder/reports/[id]/page.tsx`의 `ReportOverview` 컴포넌트). 구성:
- OVERVIEW 라벨 + AI 판정(GO/CAUTION/RECONSIDER)에 따라 자동으로 바뀌는 헤드라인 문구
- 등록 시 입력한 가설을 인용한 부제
- 문제 공감도/솔루션 수용도/구매 의향 3개를 미니 도넛으로
- 하단에 오렌지 배경의 "KEY INSIGHT" 배너(첫 번째 핵심 인사이트 또는 벤치마크 코멘트)

기존에 따로 있던 "이 프로젝트가 검증하려던 가설" 플레인 카드와 "AI 판정" 배너(`VerdictBanner`)를 이 Overview 하나로 합쳤습니다(Standard 티어만 — Light 티어는 기존 플레인 가설 카드를 그대로 유지).

### 4-5. 리뷰어별 의견 — "더보기" → 3명씩 좌우 캐러셀
처음엔 5명 넘으면 "더보기" 버튼으로 아래에 펼치는 방식이었는데, 요청에 따라 **3명씩 페이지 단위로 좌우 화살표로 넘기는 캐러셀**로 변경했습니다. 카드 자체가 아바타+프로필+성향+시나리오+페인포인트를 담은 넓은 레이아웃이라, 3장을 가로로 나란히 두면 안의 12칸 그리드가 찌그러지므로 **세로로 3장씩 쌓아서 보여주고, 그 3장 묶음 단위를 좌우로 넘기는 방식**으로 구현했습니다(`narrativePage` state, `NARRATIVES_PER_PAGE = 3`).

### 4-6. 목차 + 확대/축소

## 5. 성별/직군 매칭 게이트 이중화

- 지원/참여(apply, join) 시점에 성별 게이트가 있었는데 직군(`domain_tags`) 게이트는 없었음 → 동일하게 추가.
- 리뷰 제출 시점에는 직군 안전망만 있었는데 성별 안전망은 없었음 → 동일하게 추가.
- **이유**: 지원 절차를 우회하는 경로(초대 링크 등)가 생겨도 리뷰 제출 시점에 최종적으로 걸러지도록, 두 시점(지원/제출) 모두 성별·직군 둘 다 확인하는 이중 안전망 구조로 통일.
- 아이디어/프로토타입 단계에서 재무 정보를 입력해도 리포트에 반영 안 되는 게 에러 없이 조용히 무시되던 것 — 등록 마법사와 프로젝트 상세 화면 양쪽에 "베타 단계 이상부터 반영돼요" 안내 문구 추가.

## 6. PDF 저장 — 라이브러리 교체 이력

- **1차 시도**: `window.print()`(브라우저 인쇄 대화상자) — 사업주가 "이건 그냥 화면 캡처지 PDF 파일이 아니다"라고 명확히 반려. 게다가 인쇄 시 좌측 "리포트 목록" 사이드바(`ReportsSidebar.tsx`)를 인쇄 숨김 처리에서 빠뜨려서 그것까지 같이 찍히는 버그도 있었음.
- **2차**: `html2canvas` + `jspdf`로 교체 — 리포트 본문 DOM(`reportContentRef`)만 캡처해서 실제 `.pdf` 파일을 바로 다운로드하도록 구현. 그런데 **`html2canvas`가 Tailwind v4의 `oklch()` 색상 함수를 파싱하지 못해 캡처 자체가 실패**(`Attempting to parse an unsupported color function "oklch"` — Tailwind v4 + html2canvas 조합에서 잘 알려진 호환성 문제).
- **최종**: `html2canvas` → **`html2canvas-pro`**(oklch/lab/color-mix 등 최신 CSS 색상 함수를 지원하는 유지보수 포크)로 교체해서 해결. `package.json`에 `html2canvas-pro`, `jspdf` 둘 다 설치돼 있음 — `html2canvas`(오리지널)는 제거함.
- PDF 생성 시 확대/축소 배율을 100%로 강제 리셋한 뒤 캡처하고 끝나면 원래 배율로 복원(`handleDownloadPdf` 함수, `app/builder/reports/[id]/page.tsx`).
- **다음 담당자 참고**: 이 프로젝트에서 앞으로 다른 화면도 캔버스 캡처(스크린샷/PDF 등)가 필요하면 반드시 `html2canvas-pro`를 쓸 것 — 오리지널 `html2canvas`는 Tailwind v4 프로젝트 전역에서 계속 실패한다.

## 7. 알려진 이슈 / 다음 작업 후보

1. **직군(domain_tags) 데이터 여전히 부족** — 게이트를 추가했지만 기존 데이터는 소급 적용 안 됨. 시간이 지나 신규 지원자가 쌓이면 자연히 채워짐.
2. **인구통계별 응답 차이의 "그룹당 최소 1명" 완화가 통계적으로 유의미한지는 별개 문제** — 표본이 워낙 작아서(리뷰어 5명 수준) 이 섹션의 실질적 유용성은 리뷰어 수가 늘어난 뒤 재평가 필요.
3. **PDF 다중 페이지 슬라이싱은 단순 높이 분할 방식** — 카드가 페이지 경계에서 잘릴 수 있음(인쇄용 `break-inside: avoid` CSS와 달리 캔버스 캡처 방식은 이 속성이 안 먹힘). 완벽한 페이지 분할이 필요하면 섹션 단위로 개별 캡처 후 페이지에 배치하는 방식으로 재작업 필요 — 지금은 우선 "실제 pdf 파일 다운로드"라는 핵심 요구사항만 충족한 상태.
4. **Overview 섹션은 Standard 티어만** — Light 티어는 기존 단순 가설 카드 유지. 필요하면 Light용 Overview도 별도 검토.
5. 이전 문서(`인수인계_20260802.md`)의 미해결 항목(Van Westendorp 선택 토글, 솔루션 컨셉 A/B/C 비교 UI 등)은 이번 세션에서 다루지 않음 — 그대로 남아있음.
