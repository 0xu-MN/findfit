## 1. 관리자/리뷰어 "진행중" 숫자 불일치 수정

**증상**: 관리자 패널은 "진행 중 프로젝트"가 1개인데, 리뷰어 화면(대시보드)에는 진행중이 2개로 나옴.

**원인**: 두 화면이 서로 다른 걸 세고 있었음.
- 관리자([app/admin/page.tsx:20](app/admin/page.tsx#L20)): `projects.status === 'active'`(아직 모집 중)만 카운트.
- 리뷰어([components/evaluator/ReviewerDashboard.tsx:111](components/evaluator/ReviewerDashboard.tsx#L111)): `project_matches.status === 'accepted'`(내가 참여 중인 매칭) 개수 — 프로젝트가 `active`든 `reviewing`(3차 문서에서 다룬, 모집마감 후 리뷰 진행중 상태)이든 상관없이 셈.

3차에서 추가한 모집마감 3가지 시나리오 기능 때문에 프로젝트가 `active → reviewing`으로 넘어갈 수 있게 됐는데, 관리자 통계는 `active`만 세도록 그대로 남아 있어서 숫자가 갈렸던 것. 사용자 확인 결과 "프로젝트가 끝난 게 아니면 둘 다 진행중으로 보여야 한다"는 요구사항이 명확해서, 관리자 쿼리를 `active` + `reviewing` 둘 다 포함하도록 수정.

```ts
// app/admin/page.tsx
supabase.from('projects').select('id', { count: 'exact', head: true }).in('status', ['active', 'reviewing']),
```

## 2. 아이템 추천 mock 키워드 미반영 버그 수정

**증상**: 홈 화면 검색창에 "프리랜서 플랫폼"을 입력해도, AI 추천 결과 3개가 "아이템 정기구독 키트" / "프리미엄 아이템" / "1인 가구용 아이템"처럼 키워드가 전혀 안 들어간 제네릭한 제목으로 나옴 (Vercel 배포본에서도 재현됨).

**원인**: [lib/ai/claude.ts:109](lib/ai/claude.ts#L109) mock 응답이 프롬프트에서 사용자 키워드를 뽑아내는 정규식(`/\[사용자 입력 키워드\]\n([\s\S]*?)\n\n/`)이 실제 프롬프트 형식과 안 맞았음. 실제 프롬프트([app/api/agent/recommend-items/route.ts:87-89](app/api/agent/recommend-items/route.ts#L87))는 `[사용자 입력 키워드]` 바로 뒤에 줄바꿈 없이 설명 문장이 이어지는 구조라서( `[사용자 입력 키워드] — 반드시 이 키워드와...`), 정규식이 아예 매치되지 않고 항상 기본값 `'아이템'`으로 떨어지고 있었음.

정규식을 실제 프롬프트의 줄바꿈 구조(`[사용자 입력 키워드]` 마커 이후 첫 줄이 아니라, 빈 줄(`\n\n`) 직전의 마지막 한 줄이 키워드)에 맞게 수정:

```ts
// lib/ai/claude.ts
const keywordMatch = prompt.match(/\[사용자 입력 키워드\][\s\S]*?\n([^\n]+)\n\n/)
const keyword = (keywordMatch?.[1] ?? '').trim() || '아이템'
```

이건 mock 모드(로컬, API 실패 시 폴백)에서만 영향을 주는 수정이다 — 실제 Claude 호출이 성공하는 경우(Vercel, 키 있을 때)는 원래도 키워드를 정상적으로 반영했었음(이 정규식은 mock 전용 코드).

## 3. FindFit Agent — 홈 화면 퀴즈 답변을 무시하고 타겟을 재질문하던 문제

**증상**: 홈 화면에서 검색 → 검증 시작 → 연령대/성별/카테고리 퀴즈에 답변 → 추천 아이템 중 하나 선택 → "자세하게 조사해볼까요?" 클릭 → 프로젝트 등록 화면(`/builder/new-request`)으로 넘어가면서 FindFit Agent 채팅이 자동으로 뜸. 그런데 Agent가 이 시점에 이미 답한 연령대/성별을 전혀 모르고 있어서, "지금 어느 단계예요?" 다음에 "타겟이 누구예요?"를 처음부터 다시 물어봄. 사용자가 "이미 답변한 걸 또 물어보는 게 맞는 거냐"고 지적.

**원인 (진짜 설계 갭, mock/Claude 여부와 무관)**: 홈 화면의 아이템 탐색 퀴즈([components/creator/ItemDiscoveryFlow.tsx](components/creator/ItemDiscoveryFlow.tsx))와 FindFit Agent 채팅([components/agent/AgentPanel.tsx](components/agent/AgentPanel.tsx))이 완전히 분리된 두 시스템이었음. 아이템 카드의 "자세하게 조사해볼까요?" 버튼(`exploreItem` 함수, 구 버전 [ItemDiscoveryFlow.tsx:107](components/creator/ItemDiscoveryFlow.tsx#L107))은 `agentBubble.openWithSeed(텍스트)`를 호출해서 아이템 제목/설명만 Agent의 첫 발화로 넘겼을 뿐, 퀴즈에서 수집한 연령대/성별 답변은 어디에도 전달되지 않았음. Agent 쪽 대화 로직(`applyUnderstanding`/`generatePhaseResponse`, [components/agent/agentMock.ts](components/agent/agentMock.ts))은 항상 Phase 1(단계 파악) → Phase 2(타겟 파악)를 순서대로 밟도록 설계돼 있어서, 타겟 정보가 이미 있어도 그걸 알 방법이 없어 무조건 다시 물어봤음.

**수정 — 퀴즈 답변을 Agent 컨텍스트로 전달하고, 이미 알려진 타겟은 재질문 스킵**:

1. `AgentBubbleContext.tsx`: `openWithSeed(text: string)` → `openWithSeed(text: string, targetCustomer?: string)`로 시그니처 확장. 새 상태 `seedTargetCustomer` 추가.
2. `FloatingAgentBubble.tsx`: `seedTargetCustomer`를 `AgentPanel`에 `initialTargetCustomer` prop으로 전달.
3. `AgentPanel.tsx`: `initialTargetCustomer` prop을 받아 초기 `context` state에 `targetCustomer`로 미리 채워 넣음. 또한 Phase 1(단계 선택)에서 Phase 3(트렌드+CTA)로 곧장 넘어갈 때도 실제 트렌드 데이터가 필요하므로, 트렌드 fetch 조건을 `context.phase === 2`뿐 아니라 `context.phase === 1 && context.targetCustomer`(퀴즈에서 이미 타겟이 채워진 경우)일 때도 실행하도록 확장 — 토스트 버튼 흐름과 자유 텍스트(Claude) 흐름 둘 다 수정.
4. `agentMock.ts`:
   - `generatePhaseResponse`의 Phase 1 분기(토스트 버튼으로 단계 선택 시): `context.targetCustomer`가 이미 있으면 "타겟이 누구예요?" 질문을 건너뛰고, 곧바로 "**{타겟}** 타겟으로 이미 좁혀두셨네요!" + 트렌드 한 줄 + CTA 메시지로 Phase 3까지 한 번에 전이.
   - `applyUnderstanding`의 Phase 0/1 분기(자유 텍스트 입력, Claude 응답 처리): 마찬가지로 `context.targetCustomer`가 이미 있으면 Phase 2를 건너뛰고 바로 Phase 3으로 전이.
5. `lib/ai/prompt.ts`의 `buildAgentUnderstandingPrompt`: `phase <= 1`일 때의 `phaseInstruction`을 `context.targetCustomer` 유무에 따라 분기 — 이미 타겟이 있으면 Claude에게 "타겟은 이미 파악돼 있으니 다시 묻지 말고 검증에 대한 관심을 끌어보라"고 명시(실제 Claude 호출 시에도 재질문 안 하도록).
6. `ItemDiscoveryFlow.tsx`의 `exploreItem`: 퀴즈 답변(`answers['타겟 연령대']`, `answers['타겟 성별']`)을 조합해서 `targetCustomer` 문자열을 만들고, `openWithSeed(seedText, targetCustomer)`로 함께 전달.

이 수정은 mock 모드(로컬, API 키 없음)와 실제 Claude 호출(Vercel) 양쪽 경로 모두에 적용된다 — 토스트 버튼 흐름(`generatePhaseResponse`)은 원래도 Claude를 안 타는 순수 규칙기반 로직이라 mock/실키 여부와 무관하게 이번 수정으로 바로 스킵되고, 자유 텍스트 흐름(`applyUnderstanding`)은 mock/Claude 둘 다 동일한 스킵 로직을 타도록 처리했다.

`npx tsc --noEmit`, `npx next build` 둘 다 통과 확인.

## 4. 알려진 한계 — 로컬 테스트 시 주의할 점

이번 수정을 로컬(`localhost:3000`)에서 테스트하던 중, 사용자가 "고친 게 하나도 안 보인다"고 재현 실패를 보고함. 원인은 코드 문제가 아니라 **FindFit Agent 위젯의 상태 유지 설계** 때문이었다:

- `FloatingAgentBubble.tsx`는 크리에이터 전 화면에서 딱 한 번만 마운트되고, 페이지를 이동해도 대화 상태(`context`, `messages`)를 계속 들고 있도록 의도적으로 설계돼 있다(주석: "AgentPanel을 딱 한 번만 마운트해서 페이지를 옮겨다녀도 대화가 그대로 유지된다").
- `AgentPanel.tsx`의 `seedSentRef`([AgentPanel.tsx:294](components/agent/AgentPanel.tsx#L294))는 "시드 메시지는 최초 1회만 전송"하도록 막아놔서, 브라우저를 새로고침하지 않고 같은 세션에서 이미 한 번 Agent 대화를 시작했다면 이후 다른 아이템을 골라 다시 진입해도 새 시드 메시지(및 이번에 추가한 `initialTargetCustomer`)가 반영되지 않는다 — 예전에 열어놨던 대화가 그대로 이어질 뿐이다.
- **다음 개발자가 이 플로우를 테스트할 때는 반드시 브라우저를 완전히 새로고침(F5)한 뒤 처음부터 다시 시도해야 한다.** 탭 이동만으로는 위젯이 초기화되지 않는다.

이 "위젯이 세션 내내 유지되는" 동작 자체는 의도된 기능(리포트 화면 ↔ 프로젝트 화면 넘나들어도 대화가 안 끊기게)이라 이번에 건드리지 않았다. 다만 향후 QA/테스트 시 자주 혼란을 줄 수 있는 부분이라 기록해둔다.
