## 1. 프로젝트 개요

FindFit은 **PSF/PMF 검증 플랫폼**입니다. 크리에이터가 제품/서비스를 등록하면 리뷰어가 신청→승인→체험→리뷰 작성 과정을 거쳐 AI 분석 리포트로 이어집니다. 기술스택: Next.js 16(App Router, Turbopack) + React 19 + TypeScript + Tailwind v4 + Supabase(Postgres/Auth/Storage).

**⚠️ Next.js 16 주의사항**: 동적 라우트의 `params`가 동기 객체가 아니라 **Promise**입니다. 서버 컴포넌트는 `async` + `await params`, 클라이언트 컴포넌트는 `React.use(params)`로 언래핑해야 합니다. 이 구간 초반에 이 패턴 미적용으로 "프로젝트를 찾을 수 없습니다"가 뜨는 버그를 여러 파일에서 발견·수정했습니다(app 디렉토리 전체 재스캔 완료, 현재는 남은 곳 없음).

## 2. 이번 구간에서 완료한 작업

### 2.1 인증/온보딩 관련 버그 수정
- 소셜 로그인 후 항상 로그인 화면으로 튕기던 문제, `public.users` row 누락 시 온보딩 화면에 갇히던 문제 → `ProfileForm.tsx`를 `update`에서 `upsert`로 전환, `users` 테이블에 없던 INSERT RLS 정책 추가(마이그레이션 018).

### 2.2 NDA 최소 구현 + 랜딩페이지 카피 톤다운
- `users.nda_agreed_at`, `project_matches.nda_agreed_at`(마이그레이션 017) — 리뷰어 지원 시 기밀유지 서약 동의 시각 기록.
- 랜딩페이지에서 "NDA"(구체적 법률 문서 지칭), "법적", "유일한" 등 표현을 "기밀유지 서약/동의" 같은 일반적 신뢰 표현으로 순화.

### 2.3 크리에이터 프로젝트 삭제 기능
- 프로젝트 목록/상세 페이지에 삭제 버튼 추가. 하위 데이터(질문/답변/지원자/AI 리포트/배포 기록) CASCADE 삭제되도록 FK 수정(마이그레이션 019).

### 2.4 AI 리포트 화면 전면 재구성 (`design/findfit_creator_report5.html` 기준)
- 기존 "고급 분석"(세그먼트/감성/장벽, 한때 만들었다가 이번에 폐기) 대신, 목업 그대로 무료/유료 티어를 나눈 새 구조로 전면 재작업:
  - **무료**: PSF 게이지+서브스코어+판정, 문항별 응답 요약(review_answers 직접 집계, AI 아님), 인사이트 1번.
  - **유료(베타 기간 무료 열람)**: 인사이트 2~5, 액션 플랜, 피봇/성장 시나리오, 시장 규모(TAM/SAM/SOM), 포지셔닝 맵, Unit Economics/GTM/Scale-up 로드맵(단계별 조건부).
- `lib/ai/reportModules.ts`: `getReportModulesForStage(stage, mode)` — 단계×모드에 따라 어떤 모듈이 포함되는지 매트릭스로 명문화(기존 산발적 boolean 체크 대체).
- **외부 관심 현황 + 공유 링크 + 이메일 캡처 + 재의뢰 CTA**: `report_shares`/`report_share_events`(마이그레이션 023/024), 공개 페이지 `app/r/[slug]`, 크리에이터 쪽 통계 카드(`ExternalInterestCard.tsx`).
- 리포트 페이지 최하단에 "이 리포트는 AI가 자동 생성한 분석입니다" 고정 안내 문구 추가.

### 2.5 다중계정 방지
- **가입 시점**: 휴대폰 SMS 인증. `users.phone_verified_at` + `users.phone` UNIQUE(마이그레이션 025), `phone_verifications` 테이블. `lib/sms/solapi.ts` — 솔라피 키 없으면 mock(콘솔에 인증코드 출력). 이미 인증된 번호로 재가입 시도 시 차단. 리뷰 제출 API(`/api/reviews/[matchId]/submit`)에 `phone_verified_at` NULL이면 403 게이트.
- **현금화 시점**: 계좌 1원 인증. `reviewer_profiles.account_verified_at`, `account_verifications` 테이블(마이그레이션 025). `lib/bank/verify.ts` — PortOne 계좌인증 키 없으면 mock. 등록 즉시 `is_account_verified=true`로 두던 것을 실제 발송→코드 확인 2단계로 교체.
- **⚠️ 포인트→현금 전환 API 자체가 코드베이스에 없음** — 확인했으나 존재하지 않아 게이트를 걸 대상이 없었음. 나중에 그 기능을 만들 때 `is_account_verified` 체크를 넣을 것.

### 2.6 AI 비용 상한
- 챗봇: 프로젝트당 하루 15회(`report_chat_logs`), 질문 200자 제한, `max_tokens` 500.
- 리포트 재생성: 프로젝트당 하루 3회(`report_regenerate_logs`).
- 질문/관심사 자동추천: 프로젝트당 총 10회 또는(초안 단계처럼 project_id 없는 경우) 유저+날짜당 10회(`ai_suggestion_logs`, 범용 카운터 테이블 — `lib/ai/suggestionCap.ts`).

### 2.7 AI 엔진을 Gemini → Claude로 완전 전환
- `lib/ai/claude.ts`: `callClaude(prompt, tier: 'sonnet'|'haiku', options?)`로 파라미터화. 모델 slug는 Anthropic 공식 문서 확인 후 고정 — **sonnet: `claude-sonnet-5`**, **haiku: `claude-haiku-4-5-20251001`**.
- 리포트 생성(sonnet), 챗봇/자동추천/Agent 이해(haiku) 전부 Claude로 전환. `lib/ai/gemini.ts`는 삭제하지 않았지만 실제 호출 경로에서는 전부 빠짐(grep으로 확인 완료).
- **중요 버그 수정**: Claude Messages API는 Gemini와 달리 강제 JSON 모드가 없어서 응답이 &#96;&#96;&#96;json 코드펜스로 감싸질 때가 있음 → `JSON.parse` 실패로 "Unexpected end of JSON input"이라는 애매한 에러만 남던 것을 `extractJson()` 헬퍼로 수정. API 에러 응답(`data.type === 'error'`)도 명확히 throw하도록 수정.
- **Anthropic 크레딧 충전 완료** — 실제로 동작 확인함(2026-07-25~26 사이). 재확인 필요 시 `console.anthropic.com` → Plans & Billing에서 잔액 확인.

### 2.8 FindFit Agent Phase 1(자유 텍스트 이해) Claude 연동 — 버그 수정
- **문제**: `components/agent/agentMock.ts`는 순수 규칙기반(정규식)이라, 자유 텍스트 입력(질문형 문장 등)을 정규식이 오매칭해 "...단계시군요"처럼 사용자 발화를 그대로 되받아치는 버그가 있었음.
- **수정 범위**: 토스트 버튼 클릭 흐름과 Phase 2~4(트렌드 조회/레퍼런스/등록유도 버튼)는 전혀 안 건드림. `!isToastSelection && (phase 0 || phase 1)`일 때만 새 경로(`/api/agent/understand`, `callClaude(haiku)`)로 라우팅.
- `lib/ai/prompt.ts`의 `buildAgentUnderstandingPrompt(userInput, context)` — reply/category/stage/item_summary를 JSON으로 강제, "아이디어 이해·검증 연결" 목적에서 벗어나면 안 된다는 가드레일 명시.
- 비용 상한: `agent_understand:{user_or_session}:{date}` 키로 하루 20회. Claude 실패 시(크레딧 부족 등) 반드시 조용한 규칙기반 폴백("궁금한 내용이시군요...") — 에러 화면 노출 금지.
- **프로젝트 종료 요약 경량 이관**: `project_summaries` 테이블(마이그레이션 029) — 리뷰 제출로 리포트 생성 성공 시 `callClaude(haiku)`로 2~3문장 요약 1건 저장. 원본 대화 로그는 저장 안 함(의도적). Agent 대화 시 크리에이터의 최근 2건을 프롬프트 컨텍스트로 참고.

### 2.9 결제 인프라(테스트 모드)

### 2.10 리포트 벤치마크 로깅 + 신뢰도 3단계 표시
- `report_benchmark_logs`(마이그레이션 028) — 리포트 생성될 때마다(mock/실제 구분 없이) category+stage+psf_score 등 적재. 2단계 벤치마크용 데이터를 지금부터 축적.
- `lib/ai/confidenceTiers.ts`: `computeConfidenceTiers()` — Sean Ellis는 항상 1단계(`verified`) 고정, 경쟁사 레퍼런스/시장규모/점수 기준선은 표본이 `MIN_BENCHMARK_SAMPLE_SIZE`(현재 임시값 50, `lib/ai/constants.ts`) 이상이면 2단계(`internal_benchmark`)로 승격, "사용빈도/리텐션 신호"는 항상 3단계(`ai_estimate`, "설문 기반 예상 재방문 의향" 문구로 표기).
- `components/report/ConfidenceBadge.tsx` — 검증된 기준(녹색)/FindFit 데이터 기반(파랑)/AI 추정치(회색) 배지를 관련 섹션에 표시.
- **미구현**: "대표 리뷰어 원문 인용 최소인원 게이트" — 현재 리포트 스키마에 그런 인용 필드 자체가 없어서 재료 부재로 제외.

### 2.11 리포트 챗봇 → Agent 흡수
- 리포트 페이지의 독립 채팅 UI(`AiChatCard`) 제거, "Agent에게 물어보기" 버튼으로 교체 → `/builder/dashboard?agent=explore&reportProjectId=...`로 이동.

### 2.13 버그: 리포트 발행됐는데 리포트 메뉴에 안 보이던 문제

### 2.14 버그: 대시보드에 작성 중 프로젝트가 안 보이던 문제

## 5. 알려진 이슈 / 미완성·mock 상태

- **SMS/계좌인증 전부 mock** — 실제 문자/입금 없이 서버 콘솔(또는 API 응답의 devCode)에 코드만 찍힘. 키 발급 후 `lib/sms/solapi.ts`, `lib/bank/verify.ts`의 TODO 부분만 교체하면 됨.
- **PortOne 결제 미연동** — 브라우저 체크아웃 SDK 자체가 없음(서버 검증 함수만 완성). 게이트를 실제로 켜려면 프론트엔드에 결제창 호출 UI를 별도로 붙여야 함.
- **포인트→현금 전환 API 없음** — 계좌 인증은 되지만 그걸 소비하는 출금 기능 자체가 아직 없음.
- **대표 리뷰어 원문 인용 게이트 미구현** — 인용 기능 자체가 리포트에 없어서 재료 부재.
- **마케팅 채널별 성과/운영비용 리포트 항목** — 등록 마법사에 입력 필드가 없어 의도적으로 범위 밖(기획서 §21.5 명시).
- **`report_benchmark_logs`가 아직 실사용 데이터 없음** — `MIN_BENCHMARK_SAMPLE_SIZE=50`은 임시값, 실제 분산 관측 후 조정 필요.
