## 1. 프로젝트 개요

FindFit은 **PSF/PMF 검증 플랫폼**입니다. 크리에이터가 제품/서비스를 등록하면 리뷰어가 신청→승인→체험→리뷰 작성 과정을 거쳐 AI 분석 리포트로 이어집니다. 기술스택: Next.js 16(App Router, Turbopack) + React 19 + TypeScript + Tailwind v4 + Supabase(Postgres/Auth/Storage).

**절대 원칙(이번 구간 내내 지킨 것)**: 리뷰 제출·매칭·리포트 생성 파이프라인 API(`api/reviews/[matchId]/submit`, `api/projects/[id]/join`, `api/builder/matches/*`, `lib/ai/generateReport.ts`, `api/ai-report/*`)는 이번 구간에서 **단 한 번도 건드리지 않았습니다.** 전부 UI/위젯/신규 콘텐츠 관리 기능입니다.

### 2.1 FindFit Agent 위젯 — 상시 떠 있는 토글 + 아이콘 통일
- `components/agent/FloatingAgentBubble.tsx`: 예전엔 열림 상태에서 토글 버튼이 숨겨졌는데, 지금은 **항상 우하단 같은 자리에 떠 있고** 아이콘만 `Sparkles`(닫힘)↔`X`(열림)로 바뀌는 인터콤류 위젯 패턴으로 변경. 닫기 버튼도 카드 위에 별도로 안 뜨고 `AgentPanel.tsx`의 헤더 안에 한 줄로 통합(`onClose` prop).

## 4. 관리자 시스템 — 반드시 읽을 것

이 프로젝트는 관리자 인증이 **두 가지 완전히 별개의 방식**으로 존재합니다:

### 방식 A(기존, 여전히 존재) — 공유 비밀번호 쿠키
- `app/api/admin/auth/login/route.ts`: POST body의 `password`를 `process.env.ADMIN_SECRET_KEY`와 직접 비교. 맞으면 `findfit-admin-token` 쿠키(httpOnly, 7일) 발급.
- Supabase 계정/세션과 **완전히 무관** — 그냥 비밀번호 하나를 아는 사람이면 누구나 통과.
- 로그인 화면(`app/admin/login/page.tsx`)에서 "운영 스태프이신가요?" 링크를 눌러야 나오는 접힌 폼으로 남아있음(계정 없는 운영 스태프용으로 남겨둠).

### 방식 B(이번 구간 신규) — 실제 로그인 계정 + `is_admin` 플래그
- `supabase/migrations/031_admin_accounts.sql`로 `users.is_admin BOOLEAN` 추가, 본인이 UPDATE로 스스로 못 켜게 `REVOKE UPDATE (is_admin) ON users FROM authenticated`.
- `lib/auth/checkAdmin.ts`(신규, 공용 헬퍼): 쿠키 방식(A) **또는** `현재 로그인 세션의 users.is_admin=true` 둘 중 하나만 맞아도 통과.
- `app/api/admin/*` 아래 **12개 라우트 전부** 로컬 `checkAdmin()` 함수를 지우고 이 공용 헬퍼를 import하도록 리팩터링함(파일 목록: `insights/route.ts`, `insights/[id]/route.ts`, `users/route.ts`, `users/[id]/status/route.ts`, `requests/route.ts`, `requests/[id]/approve/route.ts`, `requests/[id]/reject/route.ts`, `distributions/route.ts`, `distributions/[id]/complete/route.ts`, `applications/route.ts`, `applications/[id]/accept/route.ts`, `applications/[id]/reject/route.ts`).
- **페이지 레벨 게이트도 별도로 있었다는 걸 처음에 놓쳤음** — `app/admin/page.tsx`(대시보드)와 `app/admin/stats/page.tsx`는 API 라우트와 별개로 자체적으로 `cookies()`를 직접 읽어 방식 A만 확인하고 있었음(방식 B 계정으로 로그인해도 못 들어감). 둘 다 `checkAdmin()` 공용 헬퍼를 쓰도록 수정 완료.
- `app/admin/page.tsx`에 "인사이트 관리"(`/admin/insights`) NavCard가 원래 없었음(만들어놓고 안내를 깜빡함) — 추가 완료.
- `app/api/auth/check-availability/route.ts`: "haloforge" 문자열이 포함된 이메일/닉네임은 다른 사용자가 못 쓰게 차단. **단, 정확히 `haloforge@haloforge.kr` / `haloforge`(정확히 이 값)는 예외로 통과** — 이 관리자 계정 본인의 재가입까지 막아버리는 버그가 있었어서 수정함(`ADMIN_RESERVED_VALUES` 배열로 정확 매칭만 예외 처리).
- `app/api/payments/process/route.ts`: `is_admin` 계정은 `FEATURES.paymentGate`가 켜져 있어도 무조건 `waived_test`로 통과(관리자는 결제 게이트 예외).
- `app/admin/login/page.tsx`: "관리자 계정으로 로그인" 폼(이메일+비밀번호, Supabase `signInWithPassword` → `users.is_admin` 확인 → `window.location.href='/admin'`)을 기본으로 보여주고, 기존 공유 비밀번호 폼은 "운영 스태프이신가요?" 링크 뒤로 접어둠(사용자가 두 폼을 헷갈려 해서 나눔).

## 5. 🔴 미해결 이슈 — 관리자 계정 로그인이 안 된다는 사용자 리포트

**사용자가 이 문서 작성을 요청한 시점까지도 "로그인이 안 된다"고 반복 보고했습니다. 여러 차례 수정을 시도했지만 최종적으로 사용자 브라우저에서 성공했다는 확인을 받지 못한 채 이 문서를 작성합니다. 다음 개발자가 처음부터 다시 진단해야 합니다.**

### 지금까지 있었던 일 (시간 순)
1. 사용자가 `/admin/login`에서 haloforge 계정 비밀번호를 입력 → "비밀번호가 틀렸다"는 에러. **원인**: 그때는 `/admin/login`에 이메일 입력칸 자체가 없고 비밀번호만 `ADMIN_SECRET_KEY`와 비교하는 방식 A뿐이었음 — 애초에 계정 비밀번호가 통할 수 없는 구조였음.
2. `/admin/login`에 이메일+비밀번호 폼(방식 B)을 새로 추가.
3. 사용자가 재시도 → "아무리 눌러도 안 열린다"고 보고.
4. `checkAdmin()`을 API 라우트에는 반영했지만 `app/admin/page.tsx`(대시보드 진입점 자체)는 놓쳤다는 걸 발견 — 방식 A 쿠키만 확인하고 있어서 방식 B로 로그인해도 `/admin` 자체가 `/admin/login`으로 다시 튕겨내고 있었음. 수정함.
5. 사용자가 재시도 → 여전히 "안 된다"고 보고. 이 시점에 `app/admin/page.tsx`의 "인사이트 관리" 카드가 애초에 없었다는 것도 같이 발견해서 추가.
6. `router.push('/admin')` (클라이언트 라우팅)이 방금 발급된 세션 쿠키를 서버 컴포넌트가 못 읽을 수 있다고 판단해 `window.location.href = '/admin'`(완전한 페이지 이동)으로 교체. 동시에 로그인 직후 `is_admin` 여부를 클라이언트에서 바로 조회해서, 실패 시 화면에 구체적 에러 문구가 뜨도록 개선(`권한 확인 실패: ...` 또는 `이 계정은 관리자 권한이 없어요`).
7. 사용자가 콘솔 로그(`forward-logs-shared.ts:95 ... HMR connected`만 있고 에러 없음)를 공유하며 "아무리 눌러도 안 된다"고 재보고.
8. **Playwright로 직접 재현 시도** (`node_modules/.bin/playwright`가 이미 설치돼 있어서 즉석에서 사용) — 헤드리스 브라우저로 `/admin/login`에 접속해 이메일 필드 + 첫 번째 비밀번호 필드(계정용)를 채우고 버튼을 클릭:
   - 처음엔 텍스트 셀렉터(`text=로그인`)가 "관리자 계정으로 로그인" 제목의 부분 문자열과 매칭돼서 잘못된 요소를 클릭 — 이건 **테스트 스크립트의 버그**였지 실제 앱 문제가 아님. `getByRole('button', { name: '로그인', exact: true }).first()`로 고치니 정상적으로 클릭됨.
   - 일부러 틀린 비밀번호로 테스트한 결과: Supabase `POST /auth/v1/token?grant_type=password`가 400을 반환했고, 화면에 "Invalid login credentials" 에러가 **정상적으로** 표시됨. 즉 **이 폼 자체(필드 인식, 클릭, fetch 호출, 에러 표시)는 코드 레벨에서 정상 동작함을 확인**.
   - **실제 haloforge 비밀번호로는 테스트하지 않았음** — 사용자 비밀번호를 알지 못하고, 요청하는 것도 부적절하다고 판단해 시도하지 않음.
9. 위 결과를 바탕으로 "아마 화면에 로그인 폼이 2개(계정용/공유비밀번호용)라 헷갈려서 아래쪽 공유 비밀번호 칸에 계정 비밀번호를 입력하고 계셨을 것"이라는 가설을 세우고, 공유 비밀번호 폼을 기본적으로 숨기고 링크 뒤로 접어두는 UI 수정을 마지막으로 적용함(이 문서 작성 직전 커밋에 포함).
10. **이 마지막 수정 이후 사용자가 실제로 재시도해서 성공/실패했는지는 확인되지 않은 채로 이 문서 요청이 들어옴.**

### 다음 개발자가 확인해야 할 것 (우선순위 순)
1. **가장 먼저**: 사용자에게 정확한 재현 절차를 다시 요청 — "`/admin/login`에서 위쪽(이메일 칸이 보이는) 폼에 정확히 haloforge@haloforge.kr과 비밀번호를 넣고 로그인 버튼을 눌렀을 때, 화면에 빨간 에러 문구가 뜨는지 안 뜨는지, 뜬다면 정확히 뭐라고 뜨는지"부터 확인. 지금까지의 모든 진단은 "에러 메시지가 안 뜬다"는 사용자의 모호한 보고에 의존했는데, 8번 항목의 Playwright 테스트로 볼 때 코드는 에러를 정상적으로 표시하므로 **실제로는 에러가 떴는데 사용자가 그 문구를 안 알려줬을 가능성**이 높음.
2. 브라우저 캐시/서비스워커 문제일 가능성 — 사용자가 강력 새로고침(Ctrl+Shift+R)을 실제로 했는지 재확인. Turbopack dev 서버가 HMR로 대부분 반영되긴 하지만, 서버 컴포넌트(`app/admin/page.tsx`, `app/admin/login/page.tsx` 자체)의 변경은 풀 리로드가 확실히 안전함.
3. 비밀번호 자체가 틀렸을 가능성 — 회원가입 시 실제로 어떤 비밀번호를 썼는지, 특수문자/공백 등이 의도치 않게 포함되진 않았는지 사용자와 함께 재확인. 필요하면 서비스 롤로 `supabase.auth.admin.updateUserById(userId, { password: '새비밀번호' })`를 써서 비밀번호를 강제로 재설정해주고 그 값으로 다시 시도해보는 것도 빠른 진단법(사용자 동의 하에).
4. `.env.local`의 `NEXT_PUBLIC_SUPABASE_URL`/`NEXT_PUBLIC_SUPABASE_ANON_KEY`가 브라우저에 정상적으로 주입되고 있는지(개발자도구 Network 탭에서 `supabase.co/auth/v1/token` 요청이 실제로 나가는지, 요청 자체가 안 나간다면 클라이언트 초기화 문제).
5. 정말 막히면, `lib/auth/checkAdmin.ts`나 `app/admin/page.tsx`에 임시로 `console.log`를 넣어 서버 콘솔(터미널, 브라우저 콘솔 아님)에 찍어보는 게 가장 확실합니다 — `checkAdmin()`은 서버 컴포넌트/라우트 핸들러에서 실행되므로 로그는 `npm run dev`를 실행 중인 터미널에 찍힙니다.

### 참고 — 직접 DB 확인용 스크립트 패턴
이번 진단에 실제로 썼던 방법(서비스 롤 키로 Node에서 직접 조회):
```js
require('dotenv').config({ path: '.env.local' });
const { createClient } = require('@supabase/supabase-js');
const supabase = createClient(process.env.NEXT_PUBLIC_SUPABASE_URL, process.env.SUPABASE_SERVICE_ROLE_KEY);
// public.users 확인
await supabase.from('users').select('id, email, is_admin').eq('email', 'haloforge@haloforge.kr');
// auth.users 확인(로그인 성공 이력 등)
const { data } = await supabase.auth.admin.listUsers();
data.users.find(u => u.email === 'haloforge@haloforge.kr');
```
`node -e "..."` 형태로 즉석 실행 가능. `dotenv`가 실행할 때마다 무작위 광고성 "tip" 문구를 stdout에 찍는데(`@dotenvx/dotenvx` 의존성) 이건 알려진 패키지 자체 동작이라 무시해도 됩니다.
